# AGENTS.md — инструкция агенту (схема LLM-вики)

> Этот файл — **schema** для LLM-агента в терминах паттерна `llm-wiki.md`.
> Он описывает структуру репозитория, правила работы с вики и требования
> к отчётам. Читайте этот файл первым при любой работе в репозитории,
> затем `wiki/index.md` (навигация по знаниям) и `wiki/wiki-schema.md`
> (конкретные правила оформления страниц).

## Роль репозитория

Исследовательский проект по физике (RPFT / UGSM / TOE / S2T). Репозиторий —
единая база: неизменяемые исходники + живая LLM-вики + схема ведения.
Работа разбита по хронологическим слоям (архив) и по типам (живой слой `s2t/`).

## Три слоя проекта (по паттерну `llm-wiki.md`)

1. **Raw sources (неизменяемые исходники)** — читать, не редактировать:
   - `архив-2025-2026/` — исторические черновики, разложены по хронологии;
   - `corpus/` — финальные тексты и PDF (статьи, тома);
   - `s2t/gates/`, `s2t/audits/`, `s2t/results/` — гейты (.tex), аудиты (.py),
     результаты (.json) живой ветки;
   - `s2t/RPFT-main/` — снапшот старого репозитория.
2. **The wiki (LLM-вики, слой знаний)** — агент владеет и поддерживает:
   - `wiki/` — см. § «Вики».
3. **The schema (этот документ + `wiki/wiki-schema.md`)** — правила, по которым
   агент ведёт вики дисциплинированно.

## Вики (`wiki/`)

Агент полностью владеет вики: создаёт, обновляет, перекрёстно связывает и
перестраивает страницы. Конкретные правила — в `wiki/wiki-schema.md`.

### Разделы

- `wiki/index.md` — навигационный каталог; читать первым при вопросах.
- `wiki/log.md` — append-only хронология действий (формат в схеме: `## [YYYY-MM-DD] action | Title`).
- `wiki/concepts/` — понятия, сущности, гипотезы.
- `wiki/sources/` — по странице на важный источник/кластер.
- `wiki/syntheses/` — сводки, мосты, эволюционные тезисы.
- `wiki/questions/` — закрытые вопросы, открытые проблемы, гейты.
- `wiki/lints/` — периодические проверки здоровья вики.

### Формат страницы

Каждая не-log страница должна иметь мета-блок:

```markdown
> Status: draft | working | mature | stale
> Type: source | concept | synthesis | question | lint
> Updated: YYYY-MM-DD
```

### Рабочие процессы

- **Ingest:** прочитать источник → обсудить выжимку → написать страницу
  в `wiki/sources/` → обновить затронутые `concepts/` и `syntheses/` →
  обновить `wiki/index.md` → дописать `wiki/log.md`.
- **Query:** начинать с `wiki/index.md`; искать по вики; отвечать со ссылками
  на страницы и исходники; ценные ответы сохранять как страницы в вики.
- **Lint:** проверять сиротские страницы, устаревшие тезисы, противоречия,
  недостающие перекрёстные ссылки и страницы; результат — в `wiki/lints/YYYY-MM-DD-lint.md`.
- **Отчёты:** см. § «Протокол отчётов».

### Связи с исходниками

- Имя файла = уникальный идентификатор. Связка гейта:
  `s2t/gates/version4_<topic>.tex` ⇄ `s2t/audits/s2t_v4_<topic>.py`
  ⇄ `s2t/results/s2t_v4_<topic>_results.json`
  ⇄ `wiki/questions/version4-<topic>-gate.md`.
- Внутри вики используйте Obsidian-ссылки `[[page-name]]`; пути к файлам —
  в бэктиках от корня репозитория (например `s2t/results/*.json`).
- Не меняйте имена файлов gейтов/аудитов/результатов: на них держатся связи.

## Именование исследований (обязательно для новых файлов)

Исследование = **триада + страница вопроса**, связанные одним стержневым токеном
`<namespace>_<topic>` (всегда snake_case для файлов, kebab-case для вики):

```
s2t/gates/    <namespace>_<topic>.tex
s2t/audits/   s2t_<namespace>_<topic>.py
s2t/results/  s2t_<namespace>_<topic>_results.json
wiki/questions/<namespace>-<topic>-gate.md
```

- **namespace** — способ нумерации/группировки:
  - версии программы: `version3_`, `version4_` и их аудиты `s2t_v3_`, `s2t_v4_`;
    следующая версия — `version5_` / `s2t_v5_` (не вводить новых схем);
  - тематические группы продолжать существующим префиксом: `wilson_`, `family_`,
    `bl_`, `majorana_`, `pati_salam_`, `state_menu_`, `su5_`, `external_`, `c6_`,
    `projector_`, `spectral_`, `tau_` и т.п.
- **topic** — краткая описательная тема на snake_case; у четырех файлов триады
  токен topic должен совпадать один к одному.
- Новую тему заводить, только если она не является частью уже существующей
  (тогда продолжать её namespace+topic). Дата в имени не используется.
- Текстовый документ без вычислений — только `s2t/docs/` или гейт `.tex`
  (без `.py`/`.json`), страница — `wiki/questions/`.
- Гарантия связности: после создания прогонять линк-аудит
  `grep -rn "s2t_<namespace>_<topic>"` и дописывать `wiki/log.md`.

## Правила модификации репозитория

- **Перемещение файлов** — только через `git mv` (сохраняет историю);
  новые файлы — через `git mv`/`git add`, затем при необходимости `git rm`.
- Не менять содержимое неизменяемых исходников (архив, гейты, результаты)
  без явной просьбы пользователя.
- Новый гейт/аудит: класть `.tex` в `s2t/gates/`, `.py` в `s2t/audits/`,
  `.json` в `s2t/results/`; страницу вопроса — в `wiki/questions/`.
- После структурных изменений обновлять `README.md`, `GLOSSARY.md`
  и дописывать `wiki/log.md`.
- Не коммитить без явной просьбы пользователя.
- Не выходить за пределы папки проекта при файловых операциях.

## Протокол отчётов (для итогов работы и статусов)

Каждый нетривиальный шаг оформлять по схеме 4-х пунктов
(см. `wiki/maintenance-agent-protocol.md`):

1. **Problem** — какая задача/проблема решается.
2. **Search for solution** — какие файлы/источники/аудиты проверены, что изменено.
3. **Expected result** — что должно быть истинно после изменения.
4. **Compliance check** — как проверено (линты, ссылки, счётчики, статусы).

Правила: отделять закрытое от открытого, не выдавать частичный успех
за полное закрытие, при структурных изменениях — запись в `wiki/log.md`.
